# sen1：16 步冷热应用复用实验

应用顺序：腾讯会议 → 浏览器 → 海泰浏览器 → 文件管理器 → WPS → 应用市场 → 腾讯会议 → 浏览器。每次进入执行启动和一次滑动，共 16 个 UI 动作。

合成页负载版本在每个应用首次进入时，将辅助进程迁入该应用的 memory cgroup，再分配 100 MiB 文件页和 100 MiB 匿名页；复用时重新访问腾讯会议和浏览器的原有页。辅助进程并非应用进程本身。加压为 16 GiB，分配完成后等待 10 秒。

运行：在 PowerShell 中执行 `./run.ps1`。结果写入本文件夹的 `results/`。原始输出目录仍保留，便于沿用已有链接。

`results/` 中的 `161726` 为失败的启动就绪检查，`161920` 是未加入合成页的短流程；`164707` 是首次合成页测试，`165901`、`170120`、`170337` 是随后三轮重复测试。比较波动时只使用后三轮。

`memory.current` 的前后差是净占用下降代理值，不是实际回收事件计数。`/proc/vmstat` 的 fault 是设备全局计数。每轮的辅助进程日志、压力日志及逐应用数值都在对应 `results/<run>/` 中。
